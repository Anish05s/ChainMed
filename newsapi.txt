Crisis Detection & Rerouting AI — User Guide (200 words)
What It Does
The system monitors real-world supply chain disruptions (floods, earthquakes, disease outbreaks) via GDELT and OpenWeather, automatically detects which routes are affected, and suggests optimized alternate transit paths using Dijkstra's algorithm.
How to Use It
1. System Monitors Continuously

Backend queries GDELT and OpenWeather every 30 minutes for disruptions.
When a disruption is detected, it creates a DisruptionEvent record with location, severity, and affected region

2. View Active Disruptions

Navigate to Crisis Dashboard in your role-based portal (Manufacturer/Supplier/Hospital)
See real-time map of disruptions, affected zones, and severity levels

3. Get Route Recommendations

System automatically calculates which supply routes are impacted
Click "View Alternative Routes" for any active shipment passing through a crisis zone
Dijkstra algorithm recommends 2–3 alternate paths ranked by distance + safety

4. Approve & Execute

Select a suggested route → System updates shipment waypoints
Estimated arrival time recalculates; all parties notified
Original supplier can decline and choose another option

5. Auto-Restock Triggered

If a crisis blocks a supplier, hospital inventory AI auto-requests emergency stock from backup suppliers

Example
Flood detected in Mumbai. System flags all routes through Mumbai Port. Supplier reroutes Chennai→Delhi→Hospital instead of direct. Hospital receives stock 2 days late but avoids counterfeit interception at flooded port.
